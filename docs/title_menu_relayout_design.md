# タイトル画面メニュー再配置 実装設計

## 1. 調査結果

- 現在のタイトル画面は scripts/game.gd の Canvas 描画で構成されている。
- assets/title/title_button_alpha.png は個別ボタンではなく、ニューゲーム、ランキング、オプションの3段をまとめた1枚の画像である。
- 終了は assets/title/title_quit_button_alpha.png の個別画像を使用している。
- パワーアップショップは現在、右下へプログラム描画されている。
- メニュー状態と決定処理はすでに5項目で、順番は「ニューゲーム、パワーアップショップ、ランキング、オプション、終了」である。

このため、既存3ボタン画像をファイルとして分割しない。描画時に既存の各領域を
draw_texture_rect_region() で切り出し、新しい共通ボタン矩形へ描画する。

## 2. 新規素材

透過済み画像:

    res://assets/title/title_power_up_shop_button_alpha.png

- 元画像と同じ 2172 x 724 px
- RGBA PNG
- 緑背景を透過し、文字・輪郭・色は描き直さない
- 実際の表示物には上下の透明余白があるため、描画時はソース領域を切り出す

推奨ソース領域:

    Rect2(Vector2(12, 103), Vector2(2148, 526))

## 3. 共通配置

1600 x 900 の基準キャンバスで、5項目を中央へ縦に並べる。

    const TITLE_MENU_BUTTON_WIDTH := 400.0
    const TITLE_MENU_CENTER_X := 800.0
    const TITLE_MENU_START_Y := 441.0
    const TITLE_MENU_GAP := 4.0

配置結果:

| index | 項目 | y |
| --- | --- | ---: |
| 0 | ニューゲーム | 約441 |
| 1 | パワーアップショップ | 約532 |
| 2 | ランキング | 約622 |
| 3 | オプション | 約713 |
| 4 | 終了 | 約804 |

全体下端は約891px。全項目の共通キャンバス描画幅を400px、横中央を800pxで統一する。
5枚共通の2694 x 584キャンバスを維持し、各画像の高さはその縦横比から自動計算する。選択枠とクリック判定には
透過キャンバスではなく、各画像の実際の外枠矩形を使用する。

プロジェクトは1600 x 900基準、canvas_itemsストレッチを使用しているため、この
基準座標を単一の正として1280 x 720から2560 x 1440まで追従させる。画面解像度ごとに
別の位置定数を持たない。

## 4. 画像の割り当て

既存3段画像は以下の領域を使用する。

    0: Rect2(8, 8, 1058, 285)       # ニューゲーム
    2: Rect2(8, 337, 1058, 286)     # ランキング
    3: Rect2(8, 666, 1057, 286)     # オプション

描画ルール:

- 5項目とも menu_buttons_v2 の個別透過PNGを使用する
- 5項目とも共通キャンバスを維持し、キャンバス描画幅を400pxに統一する
- 選択演出と入力判定は、各画像の実描画矩形を使用する
- アトラスを物理的に3ファイルへ分割しない
- 旧右下ショップパネルと旧ショップ用クリック領域は削除する

## 5. 描画と入力の単一化

次の責務を分ける。

    func _draw_title_menu_buttons() -> void
    func _draw_title_menu_button(index: int, target_rect: Rect2) -> void
    func _title_menu_button_rect(index: int) -> Rect2
    func _title_button_source_rect(index: int) -> Rect2

- _title_menu_button_rect() を描画、選択枠、マウスヒット判定の共通ソースにする。
- 選択時の拡縮を行う場合もヒット判定は基準矩形のままにする。
- 旧 TITLE_POWER_UP_SHOP_BUTTON_RECT と旧 TITLE_QUIT_BUTTON_RECT に依存しない。
- メニュー外の旧右下ショップ位置をクリックしてもショップを開かない。
- キーボード・ゲームパッドの順序は既存5項目順を維持する。
- マウス操作とカーソル表示が必ず同じindexを参照する。

## 6. ショップ固有の状態表示

ボタン本体の画像は静的素材とし、PPや解禁状態はゲーム側で重ねて描画する。

### 解禁済み

- ショップボタン右下へ小さなPP表示を重ねる
- 表示例: PP 52
- 値は描画時に PowerUpManager.current_points() から取得し、画像へ焼き込まない

### 未解禁

- ショップ画像を少し減光する
- 小さな鍵アイコンと「未解禁」を重ねる
- PP値は表示しない
- 項目自体は選択可能なままにする
- 決定時は既存 _open_power_up_shop() の解禁判定とトーストを利用する

PP・ロック表示はボタン領域からはみ出さず、ボタン名の中央文字と重ねない。

## 7. 既存挙動の維持

変更しないもの:

- タイトル背景、ロゴ、キャラクター
- ニューゲームからキャラクター選択への遷移
- ショップ、ランキング、オプションへの画面遷移
- ショップからタイトルへ戻る遷移
- 終了処理
- 解禁条件、セーブ、PP残高
- 決定・キャンセル・カーソル移動SE
- 既存の画面トランジション

通常描画経路だけでなく、DisplayTextSystem.title_menu_items() を使うフォールバック表示も
5項目かつ同じ順番へ修正する。

## 8. 実装順

1. 新規ショップボタン画像を読み込む定数とTextureを追加する。
2. 5項目共通の矩形計算関数を追加する。
3. 既存アトラスの3領域、新規ショップ画像、終了画像を共通描画へ統合する。
4. 旧右下ショップパネル描画を削除する。
5. 選択枠とマウスヒット判定を共通矩形へ統合する。
6. ショップのPP・ロック表示をオーバーレイとして追加する。
7. フォールバック用タイトル項目を5件へ修正する。
8. 自動テストと静的検証を追加する。

## 9. 検証項目

- 5項目のキャンバス描画幅がすべて400pxである。
- 各画像が元の縦横比を維持する。
- 5項目の中央x座標がすべて800である。
- y座標が前の実描画高と4px間隔から計算され、下端900以内に収まる。
- 各項目の描画矩形とマウスヒット矩形が一致する。
- 旧右下ショップ位置がクリック対象として残っていない。
- 上下入力が 0 -> 1 -> 2 -> 3 -> 4 の順に移動する。
- 初期選択がニューゲームである。
- ショップから戻った後の選択状態が既存仕様どおりである。
- 未解禁時はロック表示、PP非表示、決定時トーストになる。
- 解禁済みは現在PPが動的に表示される。
- PP変更後、タイトルへ戻ると新しい値が表示される。
- 1280 x 720、1600 x 900、1920 x 1080、2560 x 1440で欠けや重なりがない。
- テクスチャ読み込み失敗時もフォールバック表示が5項目になる。
- git diff --check とGodotのスクリプト構文チェックが通る。

## 10. 受け入れ条件

- タイトル中央に5ボタンが縦一列で表示される。
- パワーアップショップがニューゲームの直下にある。
- 既存3項目の合成画像を安全に領域描画している。
- 全項目で選択表示・入力・クリック判定が一致する。
- 旧右下ショップUIと旧クリック領域が残っていない。
- ショップ画像は透過PNGを使用し、PPと解禁状態は動的表示である。
- 既存の画面遷移、解禁、セーブ、SEに回帰がない。
