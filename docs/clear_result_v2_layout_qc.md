# クリア画面 第2版 レイアウト検証・修正設計

## 1. 検証対象

- 実画面: `C:\Users\zenih\Desktop\ss47.png`
- 基準解像度: 1600x900
- 対象: `endType == "completed"` の完走画面のみ
- 敗北画面、PP付与計算、セーブ、runId重複防止は変更しない

## 2. 確認できた不具合

### 2.1 配信ハイライトがカード外へ描画される

`_draw_result_detail_panel()` はハイライトを92px高で確保しているが、`_draw_result_trouble_card()` は固定4行に加えてボス行を追加し得る。各行は24px間隔なので、3行目以降が下端へ重なり、4行目以降はPP報酬カードへ侵入する。

### 2.2 PP報酬が小さく、空白が多い

132px高のカードに13px文字を13px間隔で配置している。通常3行では下半分が空き、項目名と金額が視認しづらい。最大6行時は縦方向へ詰め込むため、逆に可読性が落ちる。

### 2.3 最終ビルドのアイコンが小さすぎる

完走時は高さ112pxを条件に `compact_height` へ入り、装備スロットが24px、ステップ31px、レベル表示8pxになる。実画面では装備の絵柄やレベルを判別しにくい。

### 2.4 ランキング登録カードの状態判定が壊れている

高さ60px以下の分岐だけ、`rankingText` の登録判定に文字化けした文字列を使っている。`_result_ranking_card_view()` は正しく「ランキング登録」を判定する一方、枠色・アイコン・順位表示側は未登録扱いになる。

### 2.5 最大同時視聴者数が右端で欠ける

サマリー行は長いラベルで `value_x = 214` を固定し、残り幅へ25px文字を右寄せしている。`31,148 人` 程度でも末尾が欠ける。値を16文字で先に切る処理もあり、長い値へ安全に対応できない。

### 2.6 元設計の矩形配分を純粋関数化できていない

初期設計で予定した `_completed_result_detail_layout(detail_rect)` がなく、子カードの固定座標が描画関数へ直接埋め込まれている。このため、カード数追加後の高さ合計と行数の整合をテストできていない。

## 3. 修正方針

### 3.1 完走画面の外枠

1600x900基準で次へ調整する。

```text
panel          Rect2(150, 74, 1300, 746)  変更なし
summaryPanel   Rect2(180, 238, 370, 480)
detailPanel    Rect2(570, 238, 520, 480)
characterPanel Rect2(1110, 208, 310, 520)
buttons        現状維持
```

左列を20px広げ、中央列と右列の間に最低20pxの視覚余白を確保する。ヘッダー、立ち絵、ボタンへ重ねない。

### 3.2 中央列の純粋レイアウト関数

`_completed_result_detail_layout(detail_rect)` を追加し、次の子矩形を返す。

```text
内側上端: detail_rect.y + 32
内側左右: 24

highlightCard 108px
gap             8px
rewardCard    108px
gap             8px
buildCard     132px
gap             8px
rankingCard    60px
```

合計432pxで、480px高の詳細パネル内へ上下余白込みで収める。描画、テストとも同じ辞書を参照する。

### 3.3 配信ハイライト

- 表示は最大3行にする。
- 優先順は「完走結果」「ラスト指示コメ」「挑戦ボス」。
- 固定文だけの「盛り上がり」「完走ポイント」は完走タイトルと重複するため削除する。
- 1行22px以上、本文14pxを基準にする。
- 行数が増えてもカード外へ描かない。

### 3.4 PP報酬

- 項目名14px、金額14px以上。
- 1〜3行は1列、4〜6行は2列 x 最大3行にする。
- 列内の行間は18px以上。
- 下端へ区切り線と `合計 N PP` を表示する。
- 初回報酬バッジは項目名を圧迫しない位置へ置く。
- `save_failed`、`already_granted`、`unavailable` の意味は既存設計を維持する。

### 3.5 最終ビルド

- 完走画面専用スロットを36px以上、ステップ44px以上にする。
- 武器・アクセサリーの2段を維持する。
- レベルバッジは10px以上。`LvMAX` と `進化` が欠けない幅を確保する。
- 空スロットも同寸法にし、装備有無で並びを動かさない。
- 5枠が中央列内へ収まることを矩形テストする。

### 3.6 ランキングカード

- 登録判定は `_result_ranking_card_view()` の結果、または正しい `text.contains("ランキング登録")` の一系統だけを使う。
- 文字化けした比較文字列を削除する。
- 60px高では40px前後のアイコン、順位、タイトル、補足の読み順を維持する。
- 登録時はゴールド、圏外時は紫の既存色を維持する。

### 3.7 サマリー数値

- 最大同時視聴者数の値領域を最低128px確保する。
- 値を先に文字数で切らず、利用可能幅に応じて25pxから19pxまで段階縮小する。
- `999,999,999 人`、長い配信枠名、長いキャラクター名をテストする。
- ラベルと値の間に最低8px確保する。

## 4. 実装上の制約

- PP付与、残高、報酬内訳の値は変更しない。
- 表示修正から `grant_reward()`、セーブ、ランキング登録を呼ばない。
- 完走演出のスキップ、4ボタンの入力順、ショップ強調を維持する。
- `mental_breakdown` のレイアウトと描画分岐は変更しない。
- 既存の未コミット変更を巻き戻さない。

## 5. 追加テスト

- 完走用4カードが相互に重ならず、詳細パネル内へ収まる。
- ハイライト0〜3行で下端を越えない。
- PP報酬1〜6行が1列/2列へ正しく配置され、合計表示と重ならない。
- 装備5枠 x 2段が36px以上でカード内へ収まる。
- ランキング登録時に登録色、順位、タイトル、補足が表示される。
- `31,148 人` と `999,999,999 人` が欠けない。
- 1600x900論理座標を基準に、1280x720、1920x1080、2560x1440で同じ比率を維持する。
- 敗北画面の既存矩形が変更されていない。
- `git diff --check` とGDScriptパース確認を通す。
