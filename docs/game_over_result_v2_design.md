# ゲームオーバー画面 第2版 現行コード向け実装設計

## 1. 実装境界

- 対象は `endType == "mental_breakdown"` の結果画面。
- `scripts/game.gd` のCanvas描画構造と既存の結果画面入力を維持する。
- 仕様書中の `StreamResultData` / `ResultPointViewData` は新設しない。現行の `last_result_data: Dictionary` と `pointRewardView` が同じ責務を既に持つため、そのまま共通利用する。
- PP計算、付与、保存、`runId`、ランキング登録、ゲームオーバー判定は変更しない。
- クリア画面の情報構造を共通部品として使い、敗北固有差分はテーマ、トラブル行、立ち絵、セリフに限定する。

## 2. 現状との差分

現行の敗北画面には以下の差が残っている。

- 上段が評価1枚のみで、旧 `%d pt` を表示している。
- `pointRewardView` は生成済みだが、上段と中央の敗北UIで利用していない。
- 中央列が「トラブル / ビルド / ランキング」の3ブロックで、PP報酬がない。
- 敗北時は `_result_reveal_is_playing()` の対象外なので、段階表示とスキップ制御が動かない。
- 敗北時のショップボタンだけ `PP SHOP` 表記になる。
- 敗北ヘッダーに重複した説明文と不要なフォールバック文字列があり、描画順も重なりやすい。

## 3. 共通レイアウト

敗北時もクリア時と同じ1600x900基準座標を使う。

```gdscript
panel          = Rect2(150, 74, 1300, 746)
summaryPanel   = Rect2(180, 238, 370, 480)
detailPanel    = Rect2(570, 238, 520, 480)
characterPanel = Rect2(1110, 208, 310, 520)
retryButton    = Rect2(200, 742, 250, 56)
rankingButton  = Rect2(480, 742, 250, 56)
shopButton     = Rect2(760, 742, 250, 56)
titleButton    = Rect2(1040, 742, 250, 56)
```

- `_result_layout()` の `mental_breakdown` 分岐を上記へ揃える。
- 上段3パネルは `panel.position + Vector2(430, 28)`, `Vector2(800, 86)` を使う。
- プロジェクトの既存ストレッチ設定を利用し、解像度ごとの固定座標分岐は増やさない。

## 4. ヘッダー

敗北時は次だけを表示する。

```text
配信事故
メンタル崩壊
コメントに振り回された配信だった……
```

- タグ、タイトル、`summaryLine` の3要素へ整理する。
- 現行の「配信は続けられなかった……」との二重表示、および文字化けしたフォールバック文字列を削除する。
- 左側テキストは `x=88..410`、3パネルは `x=430..1230` とし、相互に重ねない。
- 背景暗転を弱め、白から薄クリームの本体パネルを維持する。赤紫は縁、タグ、薄いノイズに限定する。

## 5. 上段3パネル

### 5.1 共通化

- `_completed_metric_card_layout()` と共通の30px PPコインを再利用する。
- `_draw_result_completed_metrics()` を結果種別対応の共通入口へ拡張するか、互換ラッパーを残した `_draw_result_metrics(rect, data, outcome)` を追加する。
- 値は必ず次から読む。
  - 評価: `data.kamiRank`
  - 獲得: `pointRewardView.pointsEarned`
  - 付与前: `pointRewardView.pointsBefore`
  - 付与後: `pointRewardView.pointsAfter`
- `kamiPoint` は描画しない。

### 5.2 敗北テーマ

- 評価: 薄ピンクから薄紫、濃いピンクのランク文字。D/Cは彩度を落とす。
- S/Aでもクリア時の金色リングや祝福スパークは使わない。
- 獲得PP: クリームから落ち着いたゴールド。PPコインとカウントアップを残す。
- 所持PP: ラベンダー。`before -> after` を分離し、右側だけカウントアップする。
- カードサイズ、PPアイコンサイズ、文字の基準位置はクリア時と共通にし、テーマ色だけ差し替える。

## 6. 左列サマリー

- クリア画面と同じ7行・同じ行高を使う。
- 最大同接は `viewerCount` を表示し、`kamiPoint` や旧ptを使わない。
- 長い最大同接の縮小処理もクリア時と共通化する。
- 現行クリア画面との見た目の統一を優先し、行順は既存共通順を維持する。

## 7. 中央列

`_completed_result_detail_layout()` と同じ4区画を敗北時にも使う。

```text
配信トラブル 104px
PP報酬       116px
最終ビルド   128px
ランキング    60px
```

### 7.1 配信トラブル

純粋関数 `_mental_breakdown_trouble_rows(data)` を追加し、最大3行へ整形する。

優先順:

1. 終了理由: `deathReasonText`
2. 戦犯指示コメ: `culpritInstructionComment`
3. 最後の一撃: `finalBlowText`
4. 空きがある場合のみボス情報

- 空文字、`なし`、既知の文字化け値は非表示。
- ラベルと値を分離し、1行20px前後で描画する。
- 長い値は `_short_pause_text()` で短縮する。
- 104pxカードへ旧156px用座標を流用しない。

### 7.2 PP報酬

- `_draw_result_point_reward_card()` をそのまま使う。
- 0PP行は `pointRewardView.rewardRows` の生成側で除外済みか確認し、表示側でも0以下を描かない。
- 上段合計と中央合計は同じ `pointsEarned` を参照する。
- `already_granted` / `unavailable` / `save_failed` の既存表示を維持する。

### 7.3 最終ビルド

- クリア時の128px・5スロット構成を敗北時にも使用する。
- 内容、レベル、進化表示、空スロットは既存データをそのまま使う。
- 敗北時は枠色だけピンクから薄紫へ変更する。

### 7.4 ランキング

- クリア画面の60pxコンパクトカードを再利用する。
- `rankingText` と `rankingRegistered` を使い、順位値を再計算しない。
- ランキング保存は既存どおり最大同接ベースの `viewerCount` を使用する。

## 8. 右列

- 既存の3キャラ用敗北立ち絵を再利用する。
- クリア時と同じ310x520の表示領域へ合わせ、キャラ別のフィット補正のみ許可する。
- 下部に48pxのセリフ帯を追加する。
- `_result_defeat_character_line(character_id)` を設け、短文を返す。
  - ばんり: `やっちゃった……`
  - すぱな: `次は落ち着いていこう……`
  - まろん: `コメントに振り回されすぎたかも……`
- 割れハートと薄い悲しみ線は残すが、暗い全面エフェクトや強い点滅は使わない。

## 9. リビールと入力

- `_result_reveal_is_playing()` の対象を `completed` と `mental_breakdown` にする。
- 既存の1.67秒タイムラインとスキップ経路を共通利用する。
- 敗北時はランク拡大、コインバウンド、スパーク量をクリア時の60から75%程度に抑える。
- 敗北時もボタンはリビール完了後に表示・操作可能とする。
- 決定、キャンセル、左クリックによるスキップでは `_complete_result_reveal()` だけを呼び、結果確定やPP付与処理を再実行しない。
- スキップ入力と同じ入力でボタンまで発火させない。

## 10. 下部ボタン

- 順番は `もう一回 / ランキング / パワーアップ / タイトルへ`。
- 敗北時もショップラベルを `パワーアップ` にする。
- 直近で追加した共通の濃紫フォーカス枠、白内枠、左右マーカーを4ボタンすべてで維持する。
- 遷移処理 `_restart`, `_toggle_result_ranking`, `_open_power_up_shop("result")`, `_back_to_title` は変更しない。

## 11. データと非変更範囲

- `ResultSystem.complete_run_for_target()` は敗北時にも既にPPを計算・付与し、`pointRewardView` を構築している。
- `build_result_data()` もトラブル、PP、ビルド、ランキングに必要な値を保持している。
- 表示に不足がない限り `result_system.gd` は変更しない。
- `calculate_kami_point`, `calculate_rank`, `build_ranking_entry`, `_commit_power_up_reward`, `grant_reward` は変更禁止。
- 旧pt値をデータから削除する必要はなく、UIから参照しないだけにする。

## 12. テスト

既存 `test_clear_result_v2` のクリア回帰を維持し、敗北用テストを追加する。

- mental layoutがクリアlayoutと同じ4列・4ボタン座標を持つ。
- 上段3カードが800x86内に12px間隔で収まる。
- 敗北ヘッダー表示モデルに旧ptが含まれない。
- `pointsEarned`, `pointsBefore`, `pointsAfter` の表示元が共通である。
- 0PP行が非表示。
- トラブル行が欠損値を除外し、最大3行になる。
- 敗北時にもリビールが有効で、1.67秒後に最終値となる。
- スキップで各パネル、内訳、ボタンが即時最終状態になる。
- スキップ前後で `pointRewardView` とPP残高を変更しない。
- ボタン順と各遷移IDが変わらない。
- ランキング表示が`viewerCount`由来の既存`rankingText`を使う。
- `git diff --check`。

Godotが既に起動中なら別プロセスを起動しない。可能になった時点で1600x900を基準に、1280x720、1920x1080、2560x1440も目視確認する。

## 13. 受け入れ条件

- ゲームオーバー画面から旧`42 pt`相当が消えている。
- 上段に評価、獲得PP、所持PPが並ぶ。
- 中央にトラブル、PP報酬、ビルド、ランキングが収まる。
- PP合計、内訳、付与前後が同じデータと一致する。
- 右列に敗北立ち絵と短いセリフがある。
- 4ボタンの文言、順番、フォーカス、遷移がクリア画面と一致する。
- クリア画面の報酬、保存、ランキング、表示を壊していない。
