# クリア画面 第2.1版 上段3パネル調整設計

## 方針

既存の `CanvasItem._draw()` ベースのリザルト画面を維持し、ノードUIへ全面移行しない。
上段の `800 x 86px`、3等分、間隔12pxという基本配置は変えず、描画関数・表示モデル・演出スナップショットを分離して品質を上げる。

優先順位は次のとおり。

```text
配信完走評価 > 今回の獲得PP > 所持PP
```

評価ランク、PP報酬、付与前後残高、二重付与防止、セーブ処理は変更しない。

## 1. 描画構造

現在の汎用ループによる同型カード描画を、次の3つの専用描画へ分ける。

```gdscript
_draw_completed_evaluation_metric(...)
_draw_completed_earned_point_metric(...)
_draw_completed_owned_point_metric(...)
```

共通矩形は純粋関数で返す。

```gdscript
_completed_metric_card_layout(rect: Rect2) -> Dictionary
```

返却値：

- `evaluation`
- `earned`
- `owned`
- `gap`

基準は幅800px、高さ86px、間隔12px、各カード幅 `(800 - 24) / 3` とする。

## 2. 配信完走評価

### 配色

- ベース：`#FFD0E4`
- 右下側の薄紫差し色：`#E5D2FF`
- 外枠：`#F08CBB`、3px
- 内側補助線：半透明白、1px
- 基本文字：`#4A2A59`

単色カードにはせず、ベース面の右下へ薄紫の半透明面を重ね、軽い2色感を出す。

### 情報

- タイトル：15px
- ランク：通常42px、表示ポップ中は25～49px相当
- 内部評価ポイントは表示しない。
- ランク背後へ低透明度の円形光輪を置く。
- 星・ハート・キラキラは最大6個、文字の背後を避ける。

### ランク差分

- S：ピンク＋金。金の星と短い光輪を追加。
- A：ピンク＋薄紫。
- B：水色＋薄紫。
- C以下：薄紫＋グレー。

ランク差は純粋な表示データ関数へまとめる。

```gdscript
_completed_evaluation_style(rank: String) -> Dictionary
```

## 3. 今回の獲得PP

### 配色

- ベース：`#FFF8D7`
- 右下側：`#FFE6A6`
- 枠：`#E8BD49`、3px
- 文字：`#4A354E`
- 数値：`#C98618`

### 情報

- タイトル：15px
- 左端中央へ34px前後のPPコインを表示する。
- `+数値`：30～32px
- `PP`：18～20px。数値とは分けて描画し、数値を主役にする。
- 0PPでも位置を変えない。

PPコインは大量に生成せず、円形コイン、内周、`PP`文字、1つの光沢で構成する。

```gdscript
_draw_result_pp_coin(rect: Rect2, alpha: float, bounce: float)
```

上段の値は必ず `pointRewardView.pointsEarned` を使用し、内訳から再計算しない。

## 4. 所持PP

### 配色

- ベース：`#F1E9FA`
- 右下側：`#E7DCF5`
- 枠：`#C8AFE0`、2px
- 文字：`#4A3555`
- 矢印：`#A36BC2`
- 付与後：`#8251A6`

### 情報

1つの文字列として描画せず、次の3つへ分割する。

```text
付与前  /  矢印  /  付与後
```

- 付与前：23px
- 矢印：24px
- 付与後：28px
- 右側が常に少し強く見える固定幅レイアウトにする。
- 小さなPPコインまたは上向き線を1つだけ添える。

## 5. 表示演出

既存の `_result_reveal_snapshot()` を拡張し、描画側が時間判定を重複して持たないようにする。

追加する表示値の例：

```text
evaluationPanelAlpha
evaluationYOffset
rankScale
earnedPanelAlpha
earnedProgress
earnedCoinBounce
ownedPanelAlpha
ownedProgress
ownedArrowFlash
metricSettled
```

推奨タイムライン：

```text
0.00～0.34  評価パネル表示
0.10～0.42  ランクを 0.6 -> 1.18 -> 1.0 相当で表示
0.28～0.55  獲得PPパネル表示
0.38～0.93  獲得PPをカウントアップ
0.72～0.98  所持PPパネル表示
0.82～1.37  付与後PPをカウントアップ
1.25以降    PP内訳を順次表示
1.80前後    ボタン操作解禁
```

トップ3パネル自体は1.4秒以内に確定する。全リザルト表示は2秒を超えない。

スキップ時は既存の完了処理を使い、全値・全パネルを即座に最終状態へする。スキップでPP付与処理を再実行しない。

## 6. 表彰台アイコンの位置修正

現行 `_draw_result_podium_icon()` は、40pxアイコンでも基準点が `y + 32` に固定され、棒の下端がアイコン矩形から最大4pxはみ出す。32px表示ではさらに下へずれるため、位置ずれは実装上再現する。

固定ピクセル座標を廃止し、矩形比率から3段を生成する。

```gdscript
_result_podium_segments(rect: Rect2) -> Array[Rect2]
```

仕様：

- 外周から上下左右5px以上内側へ収める。
- 3段すべてを同じ下端へ揃える。
- 中央を最も高く、右、左の順にする。
- 3段全体の横方向重心を `rect.get_center().x` へ合わせる。
- 32px、40px、48pxの全サイズで矩形外へ出さない。
- 登録済み用キラキラは右上へ置くが、表彰台の中央軸をずらさない。

コンパクトランキングカード内では、40pxアイコンの中心をカード高さ60pxの中心 `y = 30` に合わせる。推奨配置は `card.position + Vector2(8, 10)` のままでよいが、内部形状を中央揃えする。

## 7. SE

既存SEを再利用できる場合のみ、評価、獲得PP確定、所持PP確定を0.1秒以上ずらして1回ずつ鳴らす。
専用音源がなく同じSEが3連続して耳障りになる場合は、評価と獲得PP確定の2回までとする。

スキップ時に複数SEをまとめて鳴らさない。既存の最終フィードバックSEを1回だけ鳴らす。

## 8. テスト

- 3カードが同幅、間隔12px、元の800x86px内に収まる。
- S/A/B/Cで評価表示データが変わるが、ランク値自体は変化しない。
- 獲得PPの表示元が `pointsEarned` であり、0PPでも破綻しない。
- 所持PPの左右が `pointsBefore -> pointsAfter` の順になる。
- 通常演出でトップ3パネルが1.4秒以内に最終値へ到達する。
- スキップで全表示が最終状態になり、報酬付与回数は増えない。
- 表彰台の3矩形が32px、40px、48pxの親矩形にすべて含まれる。
- 表彰台3段の下端が一致し、横方向重心が中央から2px以上ずれない。
- `git diff --check` が通る。

## 9. 変更禁止

- PP計算・付与・保存
- `runId` と二重付与防止
- 配信サマリー以下の配置
- ランキング登録判定
- キャラクター、ボタン、敗北画面
- ユーザーの既存差分
