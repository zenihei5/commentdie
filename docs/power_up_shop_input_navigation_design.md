# 『ぜんぶコメントのせいだ』
# パワーアップショップ 入力・カーソル改善設計

## 1. 目的

パワーアップショップ第1版・第2版で定義済みの入力割り当てを変えず、方向入力、決定、キャンセルに対するカーソル遷移を予測可能にする。

変更しないもの:

- PP、価格、強化効果、購入、保存、リセットの取引処理
- カード選択中の決定で即購入する操作
- Q/E、L1/R1によるカテゴリ切り替え
- Enter/Z、決定ボタンによる購入
- Esc/X、キャンセルボタンによる戻る
- カードクリックは選択、購入ボタンクリックは購入というマウス操作

## 2. 現行実装の検証結果

対象:

```text
scripts/ui/power_up_shop_screen.gd
scripts/ui/power_up_shop_card.gd
scripts/tests/test_power_up_shop_screen_v2.gd
```

確認できた問題:

1. 左右移動が4カードを一次元配列として`posmod()`している。
   - カード1から左でカード4へ飛ぶ。
   - カード2から右でカード3へ斜めに飛ぶ。
   - カード3から左でカード2へ斜めに飛ぶ。
   - カード4から右でカード1へ飛ぶ。
2. 下段カードで下を押すと、リセットボタンへカーソルを移さず確認ダイアログを即座に開く。
3. リセット確認中は左右で選択肢を移動できず、決定入力が常にリセット実行になる。
4. 仕様上の初期選択「キャンセル」が実装されていない。
5. `InputEventJoypadMotion`を受け付けないため、左スティックでカード移動できない。
6. カードのマウスホバーとキーボード選択が同時に強調され、最後に使った入力デバイスに表示が追従しない。
7. 現行V2画面テストは表示・購入・MAX・再表示を確認するが、方向遷移、ダイアログ選択、キャンセル、左スティックを検証していない。

Godot GUIエディタが実行中のため、追加のheadlessプロセスは起動せず、現行処理の分岐と仕様書を静的照合した。実装修正後は、後述の入力テストを既存V2テストへ追加し、安定した1プロセスでまとめて検証する。

## 3. カーソル状態

購入対象である`selected_index`と、現在操作している場所である`focus_area`を分離する。

```gdscript
enum FocusArea {
	CARDS,
	RESET,
	RESET_DIALOG,
}

enum DialogChoice {
	CONFIRM,
	CANCEL,
}
```

保持値:

```gdscript
var focus_area := FocusArea.CARDS
var selected_index := 0
var dialog_choice := DialogChoice.CANCEL
var last_input_device := "keyboard"
```

`selected_index`は詳細欄と購入対象を表すため、リセットへ移動しても消さない。

## 4. カードグリッド遷移

配置:

```text
[0] [1]
[2] [3]
```

期待遷移:

| 現在 | 左 | 右 | 上 | 下 |
|---:|---:|---:|---:|---:|
| 0 | 0 | 1 | 0 | 2 |
| 1 | 0 | 1 | 1 | 3 |
| 2 | 2 | 3 | 0 | RESET |
| 3 | 2 | 3 | 1 | RESET |

方針:

- 行端で左右ラップしない。
- 上端で上を押しても同じカードに留まる。
- 下段から下を押すと、ダイアログを開かずリセットボタンへフォーカスを移す。
- 移動先が同じ場合はカーソルSEを鳴らさない。
- カード数が将来変わっても、列数と配列サイズから安全に移動先を求める。固定値4への`posmod()`は使用しない。

## 5. リセットボタン遷移

`focus_area == RESET`のとき:

| 入力 | 結果 |
|---|---|
| 上 | 最後に選択していた下段カードへ戻る |
| 左 / 右 / 下 | リセットボタンに留まる |
| 決定 | リセット確認ダイアログを開く |
| キャンセル | ショップを閉じる |
| Q/E、L1/R1 | カテゴリ切替後、そのカテゴリのカードへ戻る |

カード0または1から何らかの理由でRESETへ入った場合も、上で同じ列の下段カードへ戻せるよう、`reset_return_index`を2または3として保持する。

リセットボタンにはカード選択とは別の明確なフォーカス枠を表示する。カードの選択表示は詳細対象として残してよいが、RESET側を主フォーカスとして強く表示する。

## 6. リセット確認ダイアログ

ダイアログを開いた直後:

```text
初期選択 = キャンセル
```

画面上の並びは左が「リセットする」、右が「キャンセル」のため、遷移は次とする。

| 現在 | 左 | 右 | 決定 | キャンセル |
|---|---|---|---|---|
| キャンセル | リセットする | キャンセル | ダイアログを閉じる | ダイアログを閉じる |
| リセットする | リセットする | キャンセル | リセット実行 | ダイアログを閉じる |

- 上下は現在の選択肢に留まる。
- キャンセルでショップ自体を閉じない。
- ダイアログを閉じた後はリセットボタンへフォーカスを戻す。
- リセット成功後もリセットボタンへ戻し、トーストを表示する。
- ダイアログ中はカテゴリ切替、カード購入、背後のボタン操作を受け付けない。
- 選択中のボタンへフォーカス枠を表示し、初期状態でキャンセルが選ばれていることを見た目でも明示する。

## 7. 決定・キャンセル

| 状態 | 決定 | キャンセル |
|---|---|---|
| CARDS | 選択中カードを購入 | ショップを閉じる |
| RESET | 確認ダイアログを開く | ショップを閉じる |
| DIALOG/CANCEL | ダイアログを閉じる | ダイアログを閉じる |
| DIALOG/CONFIRM | リセット実行 | ダイアログを閉じる |

MAXカードで決定した場合は何も購入せず、エラー音も鳴らさない。PP不足カードでは既存の不足演出を返す。

## 8. カテゴリ切り替え

- CARDS中のQ/EまたはL1/R1でカテゴリを切り替える。
- カテゴリごとの前回`selected_index`を復元する。
- RESET中にカテゴリを切り替えた場合は`focus_area = CARDS`へ戻す。
- ダイアログ中はカテゴリ切り替えを無効にする。
- カテゴリ切り替えでカードが再生成されても、選択・フォーカス表示を同じフレーム内で復元する。

## 9. 入力取得

方向・決定・キャンセルは、標準UIアクションを優先して判定する。

```text
ui_left / ui_right / ui_up / ui_down
ui_accept / ui_cancel
```

追加互換:

- WASD
- Z / X
- Q / E
- L1 / R1

要件:

- 左スティックを`ui_*`経由で受け付ける。
- スティックを倒し続けたときに毎フレーム移動しない。ニュートラル復帰または短いリピート間隔を持つ。
- 決定・キャンセルは1押下1回。キーエコーやボタン保持で購入・リセットを連打しない。
- ダイアログが最優先で入力を消費する。
- 処理した入力だけ`set_input_as_handled()`する。

## 10. マウスとの競合

- マウス移動を検出したら`last_input_device = "mouse"`とし、ホバー中カードだけをホバー表示する。
- カードクリック時はそのカードを`selected_index`にし、次のキーボード入力で同じカードから移動を再開する。
- キーボード、ゲームパッド入力を検出したらホバー強調を抑え、論理カーソルのフォーカス表示を優先する。
- マウスホバーだけで購入しない。
- リセット、購入、戻るをマウスで押した後も、論理カーソルの復帰先を壊さない。

## 11. 実装構造

推奨ヘルパー:

```gdscript
func _move_card_cursor(direction: Vector2i) -> void
func _set_focus_area(next_area: FocusArea) -> void
func _set_dialog_choice(next_choice: DialogChoice) -> void
func _activate_focused_target() -> void
func _cancel_current_layer() -> void
func _refresh_focus_visuals() -> void
```

入力判定と状態遷移を分け、テストでは`_handle_action()`または純粋な遷移ヘルパーを直接呼べるようにする。

## 12. 自動テスト

`scripts/tests/test_power_up_shop_screen_v2.gd`へ最低限以下を追加する。

1. 上表16方向のカード遷移。
2. 行端で左右ラップしない。
3. 下段から下でRESETへ移り、ダイアログはまだ非表示。
4. RESETで上を押すと元の下段カードへ戻る。
5. RESETで決定後、ダイアログの初期選択がキャンセル。
6. キャンセル選択中の決定でリセットされない。
7. 左で確認へ移動し、決定した場合だけ全強化がリセットされる。
8. ダイアログのキャンセル入力でRESETへ戻る。
9. カード中の決定で選択中カードだけ購入される。
10. MAXカードの決定で購入失敗SEを鳴らさない。
11. カテゴリごとの前回カード位置が復元される。
12. RESET中のカテゴリ切替でカードフォーカスへ戻る。
13. マウスホバー後のキー入力で論理カーソル表示が優先される。
14. 左スティック相当の`ui_*`入力を受理する。

テスト用Storeを使用し、ユーザーセーブを書き換えない。

## 13. 手動確認

キーボードとゲームパッドで次を一筆書き確認する。

```text
カード0 → 右 → カード1 → 下 → カード3
→ 下 → リセット → 決定 → キャンセル（初期選択）
→ 左 → リセットする → キャンセル入力 → リセットへ復帰
→ 上 → カード3 → Q/Eでカテゴリ切替 → 前回カード復元
```

追加確認:

- カーソルが対角へ飛ばない。
- ダイアログを誤って開いただけではリセットされない。
- 戻る操作が一段ずつ閉じる。
- マウスを画面上に残したままキー操作しても二重選択に見えない。
- 購入後、PP不足後、MAX到達後も同じカードに留まる。
- カテゴリ切替アニメーション後にカーソルが消えない。

## 14. 受け入れ条件

- 2x2カードが空間どおりに移動し、端で斜め・反対端へ飛ばない。
- 下段から下でリセットボタンへ移動し、決定前にダイアログを開かない。
- リセット確認の初期選択がキャンセル。
- ダイアログの選択肢を左右で選び、選択中の項目だけを決定できる。
- キャンセルはダイアログ、ショップの順に一段ずつ戻る。
- キーボード、D-pad、左スティックで同じ遷移になる。
- カード決定購入、カテゴリ別選択位置復元、マウス操作は従来仕様を維持する。
- 入力経路の自動テストが追加され、既存V1/V2テストも回帰しない。
