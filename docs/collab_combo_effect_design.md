# コラボ枠 未実装コンビ技エフェクト設計

## 1. 結論

未完成の12組を、次の2方式で完成させる。

- 先輩ユニット内の3組は、組み合わせ専用の約1.2秒の大型演出とする。
- 新人ユニットと先輩ユニットの9組は、6人分の固有モジュールを連携させ、ペア固有の受け渡し演出を挟んでシンクロバーストへ接続する。

9組を同じ汎用衝撃波だけで済ませない。一方で9本の独立した巨大描画関数にもせず、「固有モジュール」「ペアリンク」「共通フィニッシャー」の3層へ分ける。

本設計はエフェクト、画面フィードバック、SE同期を対象とする。ダメージ量、ボス割合ダメージ、即死対象、シンクロスター必要数、既存のバリアや回収効果は変更しない。

## 3. 現行基盤との接続

既存シーケンスは維持する。

| フェーズ | 現在時間 | 扱い |
| --- | ---: | --- |
| ready | 0.42秒 | シンクロスター成立通知 |
| cutin | 0.82秒 | 2人のカットインと技名表示 |
| execute | 技ごと | 本設計のワールド演出 |
| post | 1.00秒 | 余韻とゲーム復帰 |

readyとcutin中の低速化も維持する。execute中は敵や弾が通常速度へ戻るため、全面を長時間覆う演出は使わない。

専用技の既存ダメージは発動時に1回だけ適用する。専用演出内の連続斬撃や爆発は見た目のみで、追加ダメージを発生させない。

合成技は現在どおり、各モジュール開始時にそのモジュールのゲーム効果を1回だけ適用する。描画フレーム数やSE回数とダメージ回数を結び付けない。

## 5. 表示上の制約

- 背面の面塗りはalpha 0.18以下とする。
- 前面の白フラッシュは0.10秒から0.16秒、最大alpha 0.35とする。
- 画面シェイクは通常モジュールで強度0.12以下、共通決着で0.35以下、専用技の主衝撃で0.48以下とする。
- 同時に描く装飾粒子は32個まで、長い軌跡は16本までとする。
- 敵位置を読む必要がある時間帯では、画面中央の不透明画像を0.18秒以上維持しない。
- 技名は既存カットインで表示済みなので、ワールド演出へ大きな技名文字を重ねない。
- BAN、SYNC等の短い記号を使う場合も、表示時間は0.35秒以下とする。
- 描画中に乱数を引かない。発動時に`visualSeed`と配置を固定し、フレーム間のちらつきを防ぐ。
- 画像が欠落しても、円、線、ポリゴンによるフォールバックで技の順序が読めるようにする。

既存画像を実寸確認した結果、次の上限を設ける。

- モデレーター・フォートレスのパネルは中央面が濃紺で不透明なため、出現直後0.12秒はalpha 0.58以下、その後は0.32以下とする。中央へ重ね続けず、左右または下側へ逃がす。
- ファンサ・クライマックスのX斬りは高輝度かつ面積が大きいため、表示サイズを画面短辺の70%以下、主発光を0.14秒以下にする。
- 爆釣バズサムネのzoneは中央が透過しているため背面演出に使用できるが、外周の彩度が高いためalpha 0.62以下とする。

## 6. 合成技の共通タイムライン

合成技は優先度順に2人分のモジュールを実行し、最後に共通フィニッシャーを実行する。

| モジュール | 待機時間 | 見た目の寿命 |
| --- | ---: | ---: |
| きゃすみ・防御 | 0.30秒 | 0.48秒 |
| みぃむ・集敵 | 0.34秒 | 0.56秒 |
| まろん・範囲 | 0.30秒 | 0.48秒 |
| すぱな・火力 | 0.28秒 | 0.46秒 |
| りずむ・追撃 | 0.34秒 | 0.54秒 |
| ばんり・決着 | 0.38秒 | 0.58秒 |
| シンクロバースト | 0.44秒 | 0.60秒 |

2つ目のモジュール開始時に、2人のモチーフを接続する`collab_composite_link`を同時生成する。リンクは追加の待機時間を持たず、2つ目のモジュールへ重ねる。

合計execute時間は約1.02秒から1.16秒になる。既存3専用技の見た目と大きく差が出ない長さにそろえる。

### 共通フィニッシャー

`collab_composite_finish`は次の順で描く。

1. 2人の主色による細い軌道が左右から中央へ入る。
2. 軌道が2周して二重螺旋になる。
3. 中央に白金のシンクロスターが形成される。
4. 星が一度だけ強く点灯し、2人の色を交互に持つリングが外へ広がる。
5. 白い細線だけを残して消える。

現在の単色`shockwave`と「SYNC!」表示は、この演出へ置き換える。既存の敵ごとの`combo_enemy_burst`は残し、共通フィニッシャーの発光タイミングに色だけ合わせる。

## 7. 6人分の固有モジュール

### 7.1 青澄きゃすみ：モデレートウォール

effect kindは`collab_module_defense`とする。

- 画面中央を挟むように、左右と上から計3枚の半透明六角パネルが0.12秒で展開する。
- パネルは完全な壁ではなく、敵と弾が透けて見える格子状にする。
- 消去した弾の位置へ小さな六角破砕を最大6個出す。
- 最後にパネル表面を細い走査線が1回だけ通り、次モジュールの色へ変わる。

既存のモデレーターシールド画像と`moderator_shield_fx_data()`を使用する。消去位置を表示するため、弾消去処理は件数だけでなく最大6件の座標も返す。

### 7.2 紫月みぃむ：サムネサークル

effect kindは`collab_module_gather`とする。

- 対象中心へ紫色のサムネ四隅マーカーを表示する。
- 最大5本の釣り糸が外側から中心へ縮み、敵を引き寄せた方向を見せる。
- 中心に既存のgather画像を1回だけ点灯させる。
- 四隅マーカーが少し縮み、次モジュール用の「狙い枠」として0.18秒残る。

既存の`tsuri_rod_fx_data()`と`tsuri_rod_gather_fx_data()`を使用する。引き寄せ対象の発動前座標を最大5件保存し、実際の移動方向と糸の方向を一致させる。

### 7.3 白綿まろん：まろコメントリング

effect kindは`collab_module_area`とする。

- ミントとピンクのコメントバッジ12個が中央の周囲へ短く出現する。
- バッジは半周だけ回転し、2本のリングへ整列する。
- 内側リングが敵へ収束し、外側リングが範囲攻撃の到達域まで広がる。
- 吹き出しの尾の向きを中心へ向け、単なる丸粒子に見えないようにする。

既存のコメントブーメラン画像、まろコメントリングのバッジとハローを優先して使用する。画像が取れない場合は小さな角丸矩形と三角形で吹き出しを描く。

### 7.4 星投すぱな：スパチャスター

effect kindは`collab_module_firepower`とする。

- 画面の外周寄り8方向から金色の星弾が中央または強敵位置へ入る。
- 強敵が存在する場合は最大4体へ2本ずつ、存在しない場合は中央へ8本を収束させる。
- 軌跡は外側が橙、芯が白の2本線とする。
- 着弾時に小さな五角形を残し、ペアリンクがその頂点を利用できるようにする。

現在の1本だけの`star_line`を複数の固定配置へ拡張する。既存のスパチャ弾画像とシンクロスター描画を使用する。

### 7.5 灯音りずむ：ファンサラッシュ

effect kindは`collab_module_followup`とする。

- 1拍目で右上がり、2拍目で左上がりの細い斬線を描く。
- 3拍目で2本をつなぐ小さなX斬りを中央へ出す。
- 各拍の間隔は約0.10秒とし、同じフレームに3本を出さない。
- 3拍目だけ紙吹雪を最大12枚出し、次モジュールの方向を指す扇形の余韻を残す。

通常武器の`swingRight`、`swingLeft`、`finisher`を使用し、利用可能ならファンサ・クライマックスの`xSlash`、`spark`、`confetti`を追加する。

### 7.6 赤羽ばんり：BANクラッシュ

effect kindは`collab_module_finisher`を新設する。

- 前モジュールが残した中心マーカーへ、ハンマーが斜め上から落下する。
- 接地直前にハンマーの赤い残像を3枚出す。
- 接地時に小さな白い停止フレーム、赤桃色の亀裂、短いBAN印を重ねる。
- 衝撃波は共通フィニッシャーより小さくし、次のシンクロスターを隠さない。

既存のBANハンマー画像を使用する。現在の画面シェイクだけの処理を、このeffect kind生成へ置き換える。

## 8. 新人 × 先輩の9組

### 8.1 赤羽ばんり × 青澄きゃすみ

link styleは`shield_anvil`とする。

きゃすみの3枚の盾が中央下側で横一列にそろい、ハンマーを受ける「判定台」になる。ばんりのハンマーが下側中央の盾を叩くと、盾は壊れず、蓄えた青い光を赤桃色の六角破片として外へ射出する。最後に破片が中央へ戻り、シンクロスターを組み立てる。

防御と決着の組み合わせなので、破壊より「盾が衝撃を増幅する」見せ方を優先する。

### 8.2 赤羽ばんり × 灯音りずむ

link styleは`rhythm_ban`とする。

りずむの1拍目と2拍目が大きなX型ターゲットを描き、3拍目の中央へばんりのハンマーが落ちる。「1・2・BAN」のリズムで、ハンマー接地と同時にX線が赤桃色から白金へ変わる。Xの4端が内側へ折れ、シンクロスターの4本の補助光になる。

既存のBAN☆スターラッシュとの差は、星の雨ではなく、3拍とX斬りを主役にすることで出す。

### 8.3 赤羽ばんり × 紫月みぃむ

link styleは`thumbnail_smash`とする。

みぃむのサムネ枠が敵を中央へ集め、枠の中央へ大きなハンマーが落ちる。接地時にサムネ枠が一瞬白く点灯し、紫と赤桃色の小さな矩形片へ砕ける。矩形片は画面外へ飛ばさず、中央近くで回転してシンクロスターへ吸収させる。

「釣った対象をその場でBANする」流れが一目で読める構図にする。

### 8.4 星投すぱな × 青澄きゃすみ

link styleは`star_reflector`とする。

きゃすみの盾を中央左右へV字に置き、すぱなの星弾を中央へ撃ち込む。星弾は盾面で2回反射し、画面内へ扇状に分岐する。反射点に六角形と星形を重ね、最後の反射線が五角形を作ってシンクロスターへ変わる。

星弾は敵弾と区別するため、必ず白い芯と金色の星先端を持たせる。

### 8.5 星投すぱな × 灯音りずむ

link styleは`star_stage`とする。

すぱなの5つの星が中央周囲へ五角形に停止し、りずむのバトン軌跡がその頂点を1拍ずつ結ぶ。3拍目のX斬りが五角形の中央へ入ると、形全体がステージ照明のように点灯する。紙吹雪は五角形の外側へだけ飛ばし、中央の敵を隠さない。

専用技のスターコメントシャワーとの差は、降り注ぐ星ではなく「描いて完成する星」にすることで出す。

### 8.6 星投すぱな × 紫月みぃむ

link styleは`viral_thumbnail`とする。

みぃむのサムネ枠へ、すぱなの星弾が四隅と中央の計5か所へ刺さる。5点が点灯すると枠が一度だけ前へ拡大し、内側から小さな星が放射される。紫の釣り糸が星の軌道へ変わり、最後に全軌道がシンクロスターへ巻き取られる。

サムネ枠の拡大は最大1.10倍に抑え、全画面の白矩形にしない。

### 8.7 白綿まろん × 青澄きゃすみ

link styleは`moderated_comments`とする。

きゃすみの盾が半円ドームを作り、まろんのコメントバッジが外側から盾へ当たる。接触したバッジは消さず、色がミントへ変わってドーム内側の軌道へ整列する。整列したコメントが一斉に外向きへ反転し、きれいな二重リングとして広がる。

敵コメントの遮断ではなく、「コメント欄を整えて返す」穏やかな印象にする。

### 8.8 白綿まろん × 灯音りずむ

link styleは`audience_ring`とする。

まろんのコメントバッジを観客のペンライトに見立て、中央周囲へ2列で並べる。りずむの3拍に合わせて、内周、外周、全体の順でバッジが点灯する。3拍目の扇形斬りがリングを押し広げ、コメントと紙吹雪が混ざったシンクロバーストになる。

コメントバッジの動きは各拍で一度だけ変え、常時激しく回転させない。

### 8.9 白綿まろん × 紫月みぃむ

link styleは`comment_curation`とする。

みぃむの釣り糸が散らばったコメントバッジをサムネ枠へ集める。枠が縮むとバッジが円周へ再配置され、まろんのコメントリングへ変わる。サムネ四隅はそのままリングの4つのアクセントになり、最後に紫とミントの軌道としてシンクロスターへ合流する。

スターコメントシャワーとの差は、降らせる演出ではなく「選び、整列し、輪にする」演出にする。

## 9. 先輩ユニット内の専用技3組

### 9.1 ガードライブ・フィナーレ

コンセプトは「盾をステージに変え、3拍で開幕するライブフィニッシュ」。

演出時間は1.18秒とする。

| 時間 | 演出 |
| ---: | --- |
| 0.00–0.14 | 青い六角パネル3枚が左右と下側へ展開。中央は開け、弾消去位置には小さな六角破砕を表示 |
| 0.14–0.42 | りずむの右・左の斬線が入り、対応する盾パネルが順番に桃色へ点灯 |
| 0.42–0.68 | 3拍目のX斬り。全パネルへ白い格子光が走る |
| 0.68–0.94 | パネルが舞台幕のように左右へ開き、中央から青桃色の扇形ライブウェーブ |
| 0.94–1.18 | 金色の細い紙吹雪と六角光を残して消える |

利用素材:

- モデレーター・フォートレスの`panelCenter`、`panelSide`、`shockwave`、`bulletBreak`
- ファンサ・クライマックスの`swingRight`、`swingLeft`、`xSlash`、`wave`、`confetti`

SEは新規素材を必須にせず、初版では次を使う。

- 0.00秒: `moderator_shield_activate.mp3`
- 0.16秒、0.30秒、0.46秒: `fansa_baton_combo_1/2/3.mp3`

主シェイクはX斬りで0.24、ライブウェーブで0.42とする。

### 9.2 モデレート・フィニッシング

コンセプトは「散らばった画面をサムネ枠へ集め、モデレーターパネルで安全に確定する」。

演出時間は1.20秒とする。

| 時間 | 演出 |
| ---: | --- |
| 0.00–0.18 | 紫のサムネ四隅と釣り糸が出現し、中心へ向かって巻き取り |
| 0.18–0.46 | 上下左右から青い盾パネル4枚が入り、サムネ枠の外周へ固定 |
| 0.46–0.70 | パネルが順番に点灯し、内側を細い走査線が2回通過 |
| 0.70–0.94 | サムネ枠が中央へ圧縮され、白い小矩形と六角片へ変換 |
| 0.94–1.20 | 紫と青の破片が円環へ整列し、静かな白青ショックウェーブで終了 |

利用素材:

- 爆釣バズサムネの`zone`、`pull`、`line`、`targetMark`、`catchMark`
- モデレーター・フォートレスの`panelCenter`、`panelSide`、`absorb`、`bulletBreak`、`shockwaveCharged`

BAN文字は使わない。ばんりの決着技と混同させず、きゃすみらしい「整列・確定」の印象にする。

SE:

- 0.00秒: `tsuri_thumbnail_rod_cast.mp3`
- 0.20秒: `tsuri_thumbnail_rod_reel.mp3`
- 0.46秒: `moderator_shield_activate.mp3`

画面シェイクは圧縮確定時の0.30を最大とする。

### 9.3 バズ釣りフェス

コンセプトは「釣り上げた注目を3拍のライブ演出でフェスの花火へ変える」。

演出時間は1.24秒とする。

| 時間 | 演出 |
| ---: | --- |
| 0.00–0.18 | 大きなサムネマーカーと熊ルアーを中央へ投げる |
| 0.18–0.48 | 最大6本の紫の糸が外側から中心へ巻き取られる |
| 0.48–0.76 | りずむの右、左、Xの3拍斬り。各拍で枠の一辺が桃色へ点灯 |
| 0.76–1.02 | 熊ルアーが跳ね、サムネ枠の内側で紫桃色の花火が1回だけ爆発 |

## 11. ランタイムデータ

すべてのコンボエフェクトは最低限、次のフィールドを持つ。

~~~gdscript
{
    "kind": "collab_module_defense",
    "pairKey": "aosumi_kyasumi+ban_chan",
    "moduleId": "kyasumi_defense",
    "linkStyle": "shield_anvil",
    "pos": area.get_center(),
    "area": area,
    "life": 0.48,
    "maxLife": 0.48,
    "primaryColor": Color("#76E5FF"),
    "secondaryColor": Color("#FF5F91"),
    "visualSeed": 12.0,
    "targetPositions": [],
    "clearedProjectilePositions": [],
    "seStep": 0
}
~~~

`visualSeed`、対象座標、粒子角度は生成時に決める。描画関数はこのDictionaryを読み取るだけにする。

武器画像設定は発動時にweapon IDから取得し、`visualsByWeaponId`としてeffectへ複製する。描画中にJSON検索やディスク読み込みを行わない。

## 13. SE設計

初版では新規音声素材を必須にしない。

| モジュール | 使用候補 |
| --- | --- |
| ばんり | `ban_hammer_swing.mp3`、`ban_judgement_attack.mp3` |
| すぱな | `superchat_shot.mp3` |
| まろん | `comment_boomerang_swing.mp3` |
| きゃすみ | `moderator_shield_activate.mp3` |
| りずむ | `fansa_baton_combo_1/2/3.mp3` |
| みぃむ | `tsuri_thumbnail_rod_cast.mp3`、`tsuri_thumbnail_rod_reel.mp3` |
| 共通決着 | `collab_sync_star_pickup.mp3` |

SEは描画関数から鳴らさず、`_update_collab_effects()`で経過時間の閾値をまたいだ時に1回だけ鳴らす。大きなdeltaで複数閾値をまたいでも、各SEを最大1回にする。

合成技は最大3系統、専用技は最大5回までとする。同じ短音を0.08秒未満で連続再生しない。

専用SEを後から追加する場合は`seProfile`内のパスだけを差し替え、描画やゲームロジックを変更しない。

## 14. テスト設計

### 自動テスト

- 6専用技、9共通合成技の分類が維持される。
- 12組すべてが空でない`effectKind`を解決する。
- 9つのcross pairが、それぞれ異なる正しい`linkStyle`を解決する。
- すべての生成可能なeffect kindが描画ディスパッチへ登録されている。
- 各effectを進行度0.10、0.50、0.90で描画データ化した時、少なくとも1要素を返す。
- テクスチャ設定を空にしても、フォールバック描画データが残る。
- ダメージ適用回数は演出フレーム数に関係なく現在仕様と同じ。
- SEの閾値を大きなdeltaでまたいでも二重再生しない。
- stage reset、partner changed、boss transitionでeffectとSE状態が残らない。
- effectの寿命終了後に`collab_effects`から除去される。
- `git diff --check`とGodot headless parseを通過する。

### 専用プレビュー

`scripts/tests/test_collab_combo_effects.tscn`を追加し、次を切り替えられるようにする。

- 15組のペア
- 敵なし、通常敵多数、エリート1体、ボス1体
- 画面中央、画面端、画面角
- 0.0倍、0.25倍、1.0倍の再生速度
- テクスチャあり、フォールバックのみ
- SEあり、ミュート

1キーで同じ技を再発動できるようにし、乱数シードを固定する。比較用スクリーンショットでは同じ進行度を再現できるようにする。

### 視覚確認

- 12組すべてで、カットイン後0.35秒以内に最初のキャラクターモチーフが読める。
- 合成技では2人目のモチーフと受け渡しが読める。
- きゃすみ、りずむ、みぃむの演出を色なしでも形と動きで区別できる。
- 通常敵の位置、ボス本体、危険な消去不能弾を見失わない。
- 敵が0体でも演出が破綻しない。
- 画面端で画像や軌跡が不自然に切れない。
- 既存3専用技より極端に小さく、短く、または明るくならない。
- 1600×900の論理解像度と、1280×720および1920×1080への出力拡縮で確認する。

## 15. 実装順

1. `collab_combos.json`へmodule演出設定と9つのcross pair styleを追加する。
2. レジストリ検証へeffect kind、canonical pairKey、linkStyleの検証を追加する。
3. 6人分のモジュール描画を実装する。
4. 共通リンクと共通シンクロバーストを実装し、9組をプレビューする。
5. 先輩専用技3組を1組ずつ実装する。
6. 既存SEをデータ駆動で同期する。
7. 自動テストと専用プレビューシーンを追加する。
8. 12組の同条件スクリーンショットを並べ、明度、密度、サイズを最終調整する。

この順序なら、最初に現在完全に見えない3つの先輩モジュールを解消でき、その成果を9組すべてで再利用してから専用技へ進められる。
