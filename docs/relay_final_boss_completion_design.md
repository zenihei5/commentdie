# 配信リレー最終ボス「配信終了」完成実装設計

## 1. 目的

配信リレー最終ボスを、初期実装の「HP・フェーズ・指示コメ・汎用弾」段階から、正式仕様どおり最後まで遊べる完成状態へ引き上げる。

本設計は既存の配信リレー進行、通常枠、休憩画面、スコア計算を変更せず、最終ボス戦の攻撃、演出、コラボ連携、終了処理を補完する。

## 2. 現状監査

### 実装済み

- 最終ボス専用マップへの遷移とボス生成
- ボスHPバー、5フェーズ、HP閾値によるフェーズ進行
- 最終ボス用指示コメの基本処理
- 通常雑魚の停止、通常報酬の停止、固定スコアの加算
- 最終ボス戦での相方追従、通常支援、コンビ技
- プレイヤーとボスが同一tickで倒れた場合の勝利判定
- F10による最終ボス直接テスト

### 未完成・要修正

- 正式仕様の攻撃は17種類だが、専用挙動があるのは実質3種類だけで、残りは汎用の放射弾になっている。
- 攻撃候補の先頭を常に選ぶため、攻撃の偏りが大きい。
- 警告開始と同時に攻撃判定を生成しており、予告を見て回避する設計になっていない。
- `cooldown` が攻撃後の硬直と同一攻撃の再使用待ちの両方に使われている。
- 攻撃中にも指示コメ選択が割り込めるため、攻撃・指示コメ・フェーズ遷移が競合する。
- フェーズ遷移中もプレイヤー移動や一部タイマーが進む。
- コラボパスがボス本体を対象にするため、ボス撃破まで成功しない。
- コンビ技の中断処理が、今後追加する専用攻撃オブジェクトを消去できない。
- 「画面せまくする」に1秒の予告がなく、即座に縮小される。
- 勝利時の一括停止・攻撃物消去・短い決着演出が不足している。
- 固定ボスの接触ダメージ35は予告不能で、設計上の回避可能性と合わない。

## 3. 実装境界

責務を次の3層に分ける。

### `RelayBossSystem`

- ボス戦開始・終了
- HPフェーズ進行
- 指示コメ候補と効果時間
- スコアの一度だけの確定
- 攻撃システム、相方システム、ゲーム本体との調停

### 新規 `RelayBossAttackSystem`

- 攻撃候補選択
- 攻撃FSM
- 専用攻撃オブジェクトの更新
- 衝突判定、ダメージ、減速、ノックバック
- 攻撃中断と一括消去
- 攻撃ごとの再使用待ち

### 新規 `RelayBossDrawSystem`

- 攻撃予告
- レーザー、危険床、リング、レーンなどの攻撃表示
- フェーズ遷移とボス部位の簡易演出
- デバッグ表示

`game.gd` は入力・全体更新・描画呼び出しだけに留め、17攻撃の分岐を直接追加しない。

## 4. ランタイム状態

最終ボス専用状態を1つの辞書へ集約する。

```gdscript
relay_boss_runtime = {
    "active_attack": {
        "id": "",
        "state": "idle", # idle / telegraph / active / recovery
        "timer": 0.0,
        "elapsed": 0.0,
        "serial": 0,
        "substep": 0,
        "payload": {},
        "large": false,
    },
    "hazards": [],
    "reuse_cooldowns": {},
    "last_attack_id": "",
    "last_attack_was_large": false,
    "pending_comment": false,
    "pending_phase": -1,
    "gameplay_variant": "",
    "arena_warning_timer": 0.0,
    "collab_break_uid": -1,
}
```

各攻撃オブジェクトは `uid`、`kind`、`position`、`shape`、`state`、`timer`、`damage`、`hit_ledger`、`visual` を持つ。プレイヤーへのダメージは更新処理内の衝突判定からのみ発生させ、描画データは判定に使わない。

## 5. 攻撃FSM

全攻撃を次の共通状態で処理する。

```text
IDLE -> TELEGRAPH -> ACTIVE -> RECOVERY -> IDLE
```

- `TELEGRAPH`: 予告だけを表示し、ダメージ判定は持たない。
- `ACTIVE`: 攻撃物と判定を生成し、仕様どおりの時間だけ更新する。
- `RECOVERY`: 攻撃判定を消し、次の攻撃までの隙を作る。
- `interrupt()`: コンビ技、ボス撃破、画面遷移時に全状態と全攻撃物を破棄する。
- フェーズ遷移は攻撃完了後にだけ開始する。ただしコンビ技は例外として即時中断できる。

## 6. 攻撃選択

### 候補生成

- 共通攻撃3種類と現在フェーズ固有攻撃を候補にする。
- ゲーム実況フェーズは、フェーズ開始時に3種類から1系統を選び、そのフェーズ中は選ばれた系統だけを使う。
- 直前と同じ攻撃は除外する。
- 再使用待ちが残る攻撃は除外する。
- 大技の直後は共通攻撃または短い待機だけにする。
- 指示コメやコラボ破壊状態と両立しない攻撃は安全フィルターで除外する。
- 候補が空なら0.35秒待って再選択する。

### 抽選

候補の先頭固定を廃止し、設定値 `weight` による加重抽選にする。乱数はゲームが既に持つ `RandomNumberGenerator` を使い、デバッグ時に再現できるようシードを保持する。

### 時間の分離

- `recovery`: その攻撃が終わった後の硬直。
- `reuseCooldown`: 同じ攻撃を再抽選できるまでの時間。
- 通常の攻撃間隔: `baseAttackInterval * phaseMultiplier * instructionMultiplier`。
- 最短攻撃間隔は1.8秒。
- 既存の `cooldown` は移行時に `reuseCooldown` へ読み替え、各攻撃に短い `recovery` を明示追加する。

## 7. 攻撃17種類の完成仕様

### 共通攻撃

#### `comment_shotgun`

- 0.8秒、ボスからプレイヤー方向へ扇形予告を表示する。
- 予告終了時に照準方向を確定し、5発から開始、フェーズに応じて最大9発。
- 弾数増加コメ中も全体上限12発を超えない。
- 1発7ダメージ、攻撃後0.6秒の硬直。

#### `offline_laser`

- 1.1秒、プレイヤーを追尾する細い予告線を表示する。
- 予告終了時に角度を固定し、0.35秒の回避猶予を置く。
- その後0.8秒、同じ位置に太いレーザー判定を出す。
- 1回の発射につき同一対象へ1回だけ16ダメージ。

#### `noise_summon`

- 1.0秒、出現位置2か所に円形予告を表示する。
- 画面端、プレイヤー直下、他の召喚位置を避けて生成する。
- フェーズに応じて最大4体、寿命12秒、接触7ダメージ、報酬なし。
- コラボパスの有効対象にする。

### 雑談フェーズ

#### `kuso_maro_drop`

- 1.2秒、プレイヤーの現在位置と移動方向から予測した4か所へ着弾円を表示する。
- 予告終了後に上空から落下し、円内へ11ダメージ。
- 着弾位置同士は安全に抜けられる最小間隔を持つ。

#### `long_comment_line`

- 1.0秒、通過方向と幅を示す3本のライン予告を表示する。
- 予告後、各ラインが2.2秒で画面を横断する。
- 1ラインにつき同一対象へ1回だけ11ダメージ。

### ゲーム実況フェーズ

#### `race_lane_charge`

- 2本の突進を順番に行う。
- 各突進はレーン予告1.2秒、発進予告0.6秒、突進の順で処理する。
- レーンは歩行だけでも避けられる幅と間隔にする。
- 接触16ダメージ。1本目終了後に短い間を置いて2本目へ進む。

#### `game_over_barrage`

- 1.0秒、発射方向の予告を表示する。
- 4.5秒間、0.35秒ごとに6発の扇形弾を放つ。
- 扇の中心角を発射ごとに少し回転させ、固定安置を作らない。
- 1発7ダメージ。画面上のボス弾総数上限を適用する。

#### `fake_gift_trap`

- 0.8秒の出現予告後、偽ギフトを5個置く。
- 接近または寿命10秒経過で起動し、0.45秒の円形警告後に爆発する。
- 1個につき爆発は1回だけ、11ダメージ。通常ギフト報酬は発生しない。

### 歌枠フェーズ

#### `howling_ring`

- 0.9秒、ボス中心に3本のリング始点を予告する。
- 0.75秒間隔で、当たり判定を持つドーナツ形の波を3回拡大する。
- リング帯へ11ダメージ。リング中心とリング間に回避空間を残す。

#### `pitch_wave`

- 1.1秒、左右または上下の進行方向を予告する。
- 反対側の画面端から幅広い波を2本、3.0秒かけて通過させる。
- 波の間に歩行で移動できる隙間を作る。1本11ダメージ。

#### `rhythm_explosion`

- 6個の着弾マーカーを先に表示する。
- 最初の爆発まで1.4秒、以後0.25秒間隔で表示順に爆発する。
- 1個16ダメージ。隣接マーカーは回避不能な重なりを作らない。

### お絵描きフェーズ

#### `dirty_paint`

- 0.9秒、3か所の塗料範囲を予告する。
- 7秒間残り、範囲内の移動速度を0.65倍にする。ダメージは与えない。
- 同時に残る塗料の合計面積は移動可能領域の35%以下にする。

#### `eraser_sweep`

- 1.2秒、画面端から掃引する帯と進行方向を表示する。
- 1.0秒でアリーナを横断し、接触時20ダメージ。
- 端に安全余白を1か所残し、縮小アリーナ中も回避可能幅を再計算する。

#### `paint_warning`

- 1.4秒、アリーナのおよそ50%を危険色で予告する。
- 2.5秒間危険床として残り、0.6秒間隔で7ダメージ。
- ダメージ間隔は攻撃オブジェクト側の対象別タイマーで管理する。

### コラボフェーズ

#### `division_noise`

- プレイヤーと相方を分ける方向に細い帯を置き、0.8秒予告する。
- 4秒間残り、0.6秒の対象別ヒット待ちで7ダメージ。
- 命中時に小さなノックバックと1.2秒の減速を与える。
- 伝書バトのラインとは別コレクションで管理し、攻撃終了時に必ず消す。

#### `collab_break`

- 1.0秒予告後、破壊可能な妨害コアを生成する。
- HPはボス最大HPの3%、寿命10秒、撃破報酬なし。
- 存在中は相方の通常支援とコラボパスだけを停止する。追従表示とコンビ技は使用可能。
- コンビ技発動時は即座に破壊扱いにし、状態を解除する。

#### `all_genre_rush`

- 1.2秒の大技予告後、次の順で専用サブ攻撃を実行する。
- 落下攻撃2発。
- 2.5秒の弾幕。
- リング波2回。
- 消しゴム掃引1回。
- 終了後は2.0秒の明確な攻撃チャンスを作る。
- サブ攻撃は各既存コンポーネントを再利用し、汎用放射弾へ置き換えない。

## 8. 攻撃寸法と安全性

固定ピクセル値だけにせず、アリーナ短辺・長辺に対する比率として設定する。最低値と最大値を併記し、小画面や縮小アリーナでも破綻しないようクランプする。

- レーザー幅: 短辺の6%、最小28px、最大56px。
- 危険床・爆発半径: 短辺の7%から12%。
- レーン幅: 短辺の12%以下。
- 消しゴム帯: 短辺の15%以下。
- 最低回避通路: プレイヤー直径の1.75倍。
- ボス弾上限: 96。
- 予告マーカー上限: 12。
- 最終ボス召喚上限: 4。

固定ボス本体の接触ダメージは設定化し、初期値を0にする。接触ダメージを復活させる場合は、ボス移動と明確な予告を同時に設計する。

## 9. フェーズ・指示コメ・コンビ技の優先順位

優先順位を次で固定する。

1. 現在攻撃を最後まで完了する。
2. 指示コメ選択待ちがあれば、選択画面を開く。
3. 選択完了後、フェーズ遷移待ちがあれば1.5秒の遷移を開始する。
4. 遷移完了後、次フェーズの攻撃抽選を再開する。

コンビ技は例外で、攻撃を即時中断する。コンビ技終了後にHPを再評価し、最も深い到達フェーズへ1回だけ遷移する。複数閾値を飛び越えた場合も古いフェーズ演出を連続再生しない。

フェーズ遷移中は、プレイヤー、相方、ボス、攻撃物、召喚、効果時間タイマーをすべて停止する。UI演出用タイマーだけを進める。

## 10. 最終ボス指示コメ

各効果は独立した終了時刻を持たせ、共通タイマーの上書きで早く切れないようにする。候補は直前に選んだ1件だけでなく、直前に提示した3件も避ける。

- 攻撃速度0.75倍: 攻撃間隔にだけ適用し、予告時間は短縮しない。
- 弾数1.4倍・弾速1.1倍: 弾数上限、回避通路、全体弾数上限を守る。
- ダッシュ禁止: ダッシュ前提になる攻撃配置を安全フィルターで除外する。
- 相方ミュート: 通常支援とコラボパスを止め、追従表示とコンビ技は維持する。
- アリーナ縮小: 1.0秒の枠予告後に75%へ縮め、プレイヤーと相方を新しい範囲内へ補正する。
- 回復禁止: 回復アイテム、レベルアップ回復、休憩由来の戦闘中回復を共通入口で防ぐ。

効果終了時は、その効果が変更した値だけを戻す。他の指示コメや攻撃状態を一括初期化しない。

## 11. コラボ連携

### コラボパス

- 最初のパスはボス戦開始12秒後。
- 以後は通常20秒、最終フェーズ12秒。
- 対象は `relayBossSummon` のみ。ボス本体を対象にしない。
- 対象がいなければ失敗表示を出さず、3秒後に再探索する。
- 成功報酬はシンクロスターだけで、スコア・経験値・通常ドロップは発生させない。

### コンビ技

- ボス最大HPの6%ダメージ、上限8%を既存設定どおり使用する。
- 演出中はプレイヤー無敵。
- 発動時に全ボス弾、専用攻撃物、ノイズ、召喚、コラボ妨害コアを消す。
- 攻撃FSMを `interrupt()` し、演出終了後にフェーズ判定する。

## 12. 勝利・敗北・スコア

- ボス開始時に固定スコア計算用の値をスナップショットする。
- 固定スコア加算は `score_awarded` フラグで一度だけ行う。
- 同一tickでプレイヤーHPとボスHPが0以下なら勝利を優先する。
- 勝利確定時に攻撃抽選、指示コメ、召喚、相方パス、全攻撃物を停止・消去する。
- ボス撃破アニメーション、短い静止、`RELAY COMPLETE` の順で既存リザルトへ接続する。
- 敗北時も同じ一括クリーンアップを通し、次回開始へ状態を持ち越さない。

## 13. 設定データの追加項目

各攻撃に最低限、次を追加する。

```json
{
  "weight": 1.0,
  "telegraph": 1.0,
  "activeDuration": 1.0,
  "recovery": 0.6,
  "reuseCooldown": 8.0,
  "large": false,
  "tags": ["projectile"],
  "requiresFullArena": false
}
```

既存キーは可能な限り維持し、読み込み側で後方互換の既定値を持たせる。攻撃の形状・速度・半径・上限などはコードへ散在させず、`relay_mode.json` の最終ボス攻撃定義へ集約する。

## 14. デバッグ機能

- F10: 現在の最終ボス直接開始を維持。
- デバッグメニューまたはキーで攻撃IDを指定して強制開始。
- フェーズを1段階進める操作。
- 攻撃FSM状態、残り時間、再使用待ち、危険物数を表示するオーバーレイ。
- 固定乱数シードで同じ攻撃列を再現可能にする。

## 15. 検証項目

### 自動・ヘッドレス確認

- JSON構文チェック。
- Godotヘッドレス起動とスクリプト構文チェック。
- 17攻撃IDすべてが専用ハンドラへ解決され、汎用フォールバックへ落ちないこと。
- 攻撃の `TELEGRAPH` 中にダメージ判定が存在しないこと。
- 同一攻撃が連続せず、再使用待ちを守ること。
- コンビ技中断後に攻撃物が0になること。
- 勝利・敗北後に最終ボス専用オブジェクトが0になること。

### 手動確認

- 17攻撃を1つずつ強制発動し、予告と判定が一致する。
- 通常移動だけで回避可能な配置が毎回1か所以上ある。
- ダッシュ禁止とアリーナ縮小が重なっても回避不能にならない。
- 指示コメ選択、フェーズ遷移、コンビ技が競合して停止しない。
- 相方パスが召喚だけを狙い、対象なし時に3秒後再試行する。
- 最終フェーズから勝利、リザルト、ランキングまで完走できる。

## 16. 完了条件

- 17種類すべてに見た目・予告・判定・終了条件が異なる専用実装がある。
- 攻撃選択、指示コメ、フェーズ遷移、コンビ技の順序が本設計どおり安定する。
- 最終ボス戦の開始からリザルトまで、停止や攻撃物残留なく完走できる。
- 既存の配信リレー進行、休憩、通常枠、スコア計算を回帰させない。
